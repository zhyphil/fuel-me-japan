# 手机版地图动态高度（2026-10-01）

用户反馈：iPhone 首页地图下方仍有空白，希望地图自动填满剩余高度。

## 修改

页面原本使用 `100svh`，浏览器工具栏收起后仍按较小可视高度布局。改为优先使用 `100dvh`，保留原单位作为兼容回退，现有弹性布局将多出的空间分配给地图。固定页头、筛选区域与底部数据说明占用的空间仍被扣除；小屏或横屏保留地图最小高度与正常页面滚动。已有地图尺寸观察器会同步调整地图，无需新增监听器或重复创建地图。

[Chrome 官方说明](https://developer.chrome.com/blog/new-in-chrome-108)区分了小视口、最大视口及动态视口。此处只调整布局，不改数据、定位、广告配置或业务功能。

## 验证

- 先在旧代码复现：可视高度932px、小视口812px，底部出现120px留白，断言失败。修复后同一场景通过，新增空间由地图填充。
- `npm run check`通过：lint、类型检查、363项单元测试、静态构建及385项Chromium浏览器检查。
- 新增7项高度检查：五语言在430×760、430×932、390×1050下的全国概览与东京分区；工具栏大小视口差异；320×568与932×430横竖屏；地图署名与控件边界；数据说明展开收起。该组连续运行3次，共21项通过。
- WebKit通过6项；仅Chromium提供的工具栏差异模拟1项明确跳过，其余五语言及旋转检查均执行。WebKit与手机视口模拟不代表实体iPhone Chrome验收，真机仍需用户复测。
- 第一轮完整检查384项通过、1项失败：旋转后先后读取的两个元素边界相差7.59px。已将相关边界改为同一次浏览器读取，并等待布局条件成立，不放宽2px容差；最终完整检查通过。
- 一轮WebKit检查与构建重写预览文件重叠，前两页未出现地图；构建结束后单独运行，6项通过、1项跳过。该中间失败未计入验收通过。

证据保存在`reports/evidence/m01/mobile-map-height-20261001/`。离线截图的底图为空白测试夹具，生产截图另行记录。测试自动改写的历史截图已恢复，本轮没有改写旧报告或主目录的用户更改。

## Initial snapshot validation

- 22,098 exported fuel geometry representations reduce to **16,454 typed OSM objects** after removing 5,644 duplicate representations of closed ways: 10,760 nodes, 5,652 ways, 42 relations.
- Exactly 47 complete OSM prefecture boundaries; all stations assigned once, zero unmatched/ambiguous memberships. Independent geometry scan matched every prefecture's output count. No invalid station or prefecture geometries in this source.
- This is partial OSM coverage, not a claimed complete inventory or real-world business deduplication. Position can be an area representative point, not an entrance.
- Transformation `m01-data-v2`: 875 SELF, 65 FULL and 15,514 UNKNOWN service records. Missing and conditional fuel/payment/service observations stay UNKNOWN; no inferred foreign-card acceptance, no guessed vehicle fuel, no station prices.
- Official output: exactly **141 reference records**. Parent independently compared all 47 × 3 values and survey/publication dates with the original workbook. No regional totals, previous-week columns or kerosene were used. Reference basis: cash, tax included, JPY/L.
- Every manifest artifact is checked by SHA-256 and byte count; regional/source/price schemas and cross-source consistency also gate every build.

## Implemented checks

The importer has 16 passing Python tests covering geometry/typed deduplication, UNKNOWN, mixed/conditional attributes, count gates, official sheet coverage/header/unit/date/value checks, source hashes, HTTP 403, parse failure and simulated final-pointer promotion failure. Regression cases were first observed failing and then passed after fixes. Existing TypeScript data tests cover all actual partitions, hashes, uniqueness, runtime schema guards, adjacent-region lookup, Haversine order and corrupt/aborted fetches. Final aggregate app and browser counts belong in `M0.1-completion.md`.

## Refresh status and limitations

The offline import and automatic discovery/check commands are implemented, together with a weekly OSM / publication-day price candidate workflow. No push or production deployment is performed by these commands. The workflow is local and has not run on GitHub; activation requires a reviewed default-branch release. Candidate artifacts are reviewed before release.

Official server HTTP requests returned 403 in this environment. The official browser download succeeded, so the initial source is real and parsable; **unattended official-price fetching is not verified and remains blocked here**. No alternate source or scraping workaround was used. Source failure keeps the released last-known-good snapshot, with visible survey dates and age notice in the UI.

## Result

Primary site: https://fuel-me-japan.com/ (Simplified Chinese: https://fuel-me-japan.com/zh-Hans/).

- Apex and `www` are active custom domains on the existing `fuel-me-japan` Cloudflare Pages project; both validation and certificate status are active.

- Always Use HTTPS is enabled. Public requests validate the TLS certificate without bypass flags.
- An account Bulk Redirect list named `fuel_me_japan_domains` redirects `www.fuel-me-japan.com/` and `fuel-me-japan.pages.dev/` to `https://fuel-me-japan.com/` with status 301. It matches subpaths and preserves path suffixes and query strings. `include_subdomains=false` keeps deployment previews accessible.
- Static canonical URLs and all five language alternates now use the primary HTTPS domain. The English root points canonically to `/en/`.
- Foundation `noindex, nofollow`, robots disallow, privacy restrictions and disabled future features remain intact.

## Scope and maintenance

This is domain configuration for the foundation preview, not business-feature or human acceptance. Original 00–10 specifications and the original M0.0 completion report remain unchanged. No data integration, new infrastructure runtime, or later milestone was implemented.

Mail-related DNS records appeared while this setup was running. They were preserved; this task made no mail configuration changes and did not test email delivery. Domain registration, billing and account-level policies were not altered.

DNS and Bulk Redirects are Cloudflare configuration, separate from the static repository deployment. Resource IDs and exact redirect settings are saved in the configuration evidence. For an authorized rollback, disable the `fuel_me_japan_primary_domain` rule first to restore direct access to the old production hostname; then roll the Pages deployment back if needed. Do not replace the whole DNS zone or account ruleset, as that could remove unrelated records or later rules. No rollback was performed.

Implementation references: [Pages custom domains](https://developers.cloudflare.com/pages/configuration/custom-domains/), [redirect a Pages production hostname](https://developers.cloudflare.com/pages/how-to/redirect-to-custom-domain/), [Bulk Redirect API](https://developers.cloudflare.com/rules/url-forwarding/bulk-redirects/create-api/). Host-level redirects use Cloudflare Bulk Redirects; Pages `_redirects` does not support domain-level redirects.

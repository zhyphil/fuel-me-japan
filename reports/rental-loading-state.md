# 还车门店目录加载状态与布局修复

日期：2026-10-01。工作区：`fuel-find`；基线：`fd315a1`。本次为用户提出的首次加载布局修复，仅本地实现与验收。

## 完成结果

标题、说明和搜索表单从静态页面首次显示起就完整保留。应用代码和门店数据分别加载时，继续使用同一套布局；目录容器明确占满可用宽度，避免原先等待时变窄、出现结果后再撑开的横向跳动。

结果区预留高度，靠上方显示转圈、加载提示和“暂未显示门店，加载完成后将在这里显示匹配结果。”，手机上更容易看到加载状态。加载期间表单暂不可操作，公司下拉显示“正在加载…”。数据就绪后启用搜索并显示真实条数、地图和分页列表。

加载与空结果分别处理：等待中不显示虚假的“0 条匹配记录”；搜索完成且确实没有匹配项时，显示 0 条及“没有匹配记录，请调整地区、公司或名称。”。加载失败则显示错误和重试按钮，标题与表单继续保留。开启减少动画时保留加载符号但停止旋转。

五种语言均已补充对应文字。首页仍按需进入租车业务，未改动候选数据、搜索规则或既有业务范围。

## 原因与实现

原先有三个不同的渲染阶段：静态页面只显示简化标题，业务代码加载后显示加载文字，门店数据完成后才挂载表单；同时主容器只设置最大宽度，等待期间会按内容收缩。

新增 `RentalDirectoryFrame.tsx`，让静态页面、代码加载占位和已加载目录共用介绍与筛选组件；在 `App.tsx`、`RentalBusiness.tsx` 和 `RentalDirectory.tsx` 中接入。`styles.css` 补齐容器宽度与等待、空结果、错误状态的样式。

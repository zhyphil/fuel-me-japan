**必须做的最小方案**

1. **统一绘制调度，动画结束后再调整聚合结构。**

   在 `FuelMap` 内用一个 `requestAnimationFrame` 调度入口承接地图事件、props 更新及 ResizeObserver；已有任务时只标记脏状态，不反复取消再排队。

   ResizeObserver 只安排尺寸处理；同一帧先 `invalidateSize()`，再统一提交一次绘制。卸载时取消任务并清理监听器。隐藏地图尺寸为零时暂停几何处理，重新显示后补一次。

   用公开 `zoomstart`、`zoomend` 维护动画状态：期间保留已有 Marker，由 Leaflet 更新位置；结束后统一重算及增删。不要在 `zoom`、`zoomanim` 每帧聚合。

   Leaflet 实际顺序是：移除动画 class → 更新位置并发出 `zoom` → `zoomend` → `moveend`。因此在结束事件之后的统一帧提交结构变更，可以避免中途替换动画中的节点；不需要猜测并等待固定 250ms。

2. **拆开“构建聚合”与“视口裁剪”。**

   在 `map-view.ts` 保留现有行为，拆出全部分桶结果和视口筛选两个步骤：

   - 地区锚点只随 manifest 引用变化重新计算。
   - 聚合缓存绑定当前地图实例、数据引用、overview 模式、**实际缩放值**及网格尺寸。
   - 平移、尺寸变化仅筛选缓存中的聚合中心，不重新投影全部记录。
   - 语言、油种、价格、选中态变化只更新展示内容。
   - 保留地区 84px、站点 116px 网格，以及视口外一格的现有边缘规则。

   `FindFuel.tsx:176–177` 已通过 `useMemo` 保持价格与筛选结果引用，第一版无需增加全局数据版本机制。缓存只保留当前组合，避免积累全部缩放级别。

3. **按稳定身份更新 Marker 和按钮，保留焦点。**

   用 `Map<key, MarkerEntry>` 替代 `clearLayers()`：新增、更新和删除有差异的项；保留不变的 Marker、button、图片节点。位置、选中状态及文本变化分别更新，避免无条件 `setIcon()`。

   单站用站点 ID，单地区用 code；聚合用成员身份构成的确定性 key，区分地区和站点。不能只用网格坐标作为跨缩放身份。保留现有单站、单地区 `data-map-key`，兼容已有测试。

   点击监听器读取 Entry 的最新成员和 `latest.current`，避免复用节点后打开旧成员。价格从有变无时必须删除价格条，同时更新无障碍标签。

   焦点处理要求：
   - 节点保留时不重复调用 `focus()`。
   - 聚合拆分、合并后，通过原成员 ID 找到新目标。
   - 目标确实消失才回到地图。
   - 调度期间用户已移到工具栏或详情时，不抢回焦点。
   - `focusStation()` 支持绘制完成后兑现焦点请求，避免与父组件关闭详情的 rAF 竞态。

4. **给聚合点击增加过渡，单独处理连续滚轮。**

   两处聚合点击采用公开 `setView()` 动画选项，遵循 `prefers-reduced-motion`；键盘焦点在最终绘制后转移。保留最大缩放成员列表、同位置地区选择逻辑。

   普通模式保留 Leaflet marker 动画。**不要通过关闭 `markerZoomAnimation` 消除卡顿**：源码会给这些标记添加 `leaflet-zoom-hide`，动画期间隐藏它们。

   如果父级复现确认连续输入被动画锁吞掉，本次应增加一个地图专用滚轮协调器：
   - 通过公开 API 关闭内置滚轮 handler，并用 `L.DomEvent.getWheelDelta()` 归一化输入。
   - 累积目标缩放及鼠标锚点；动画期间保留输入，包括反向输入。
   - 在公开结束事件后提交最新目标，使用 `setZoomAround()`；控制器自己发命令时立即记录待完成状态。
   - 保持缩放边界、步进和现有灵敏度语义，卸载时清理监听器、定时器和待执行目标。

   **不能只增加 `wheelDebounceTime`、缩短 CSS 时间，或改成 `animate:false` 就宣称不丢手势**；动画锁判断发生在该选项判断之前。若父级未复现输入丢失，先交付前三项及点击过渡，避免未经验证重写手势行为。
